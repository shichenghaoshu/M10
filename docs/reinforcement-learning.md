# RL、PPO 与 Sim-to-Real

RL 即强化学习，不是另一个与强化学习并列的技术。策略根据观测输出动作，环境给出奖励，训练算法更新策略。

## OpenBeni 的公开例子

- 观测包含姿态、关节角 / 角速度、速度命令和上一步动作。
- 公开动作顺序包含 4 个腿关节位置、2 个轮子速度和 1 个主动云台角，共 7 维。
- 奖励涉及速度和姿态跟踪，惩罚包含力矩、关节加速度、姿态偏离及越界。
- 使用 MuJoCo / mjlab 与 PPO 训练，支持导出 ONNX / MNN。

公开的 velocity tracking 是给定速度的运动控制，不等于视觉识别并锁定一个人。商业视觉跟随能力与公开运动仿真源码需要分开说明。

## M10 的落地计划

1. 为自己的质量、轮径和执行器拓扑建立仿真模型。
2. 测量延迟、死区、持续输出能力与反馈周期。
3. 随机化质量、摩擦、驱动力及通信延迟。
4. 在 GPU 上训练，与现有 P / PD 基线比较。
5. 导出并核对观测顺序、归一化、动作尺度及循环状态。
6. 从架空限速到低速实机，记录失稳、超时、停车时延及异常恢复。

Beni 的 7 维策略不能直接用于两驱 M10。更换形态或执行器后要重建动作空间并训练 / 评估。当前仓库没有 M10 RL 权重，也不声称已经部署 RL。

参考：[OpenBeni](https://github.com/Mondo-Robotics/open-beni/tree/4545b86a131d05519050df11a424368ef9f06b4f)、[PPO 原论文](https://arxiv.org/abs/1707.06347)、[幻尔训练介绍](https://forum.hiwonder.com/t/how-wonderduck-learns-to-walk/463)。

## OpenBeni 的观测和动作到底是什么

以下固定到上述提交的 [beni_velocity_flat_env_cfg.py](https://github.com/Mondo-Robotics/open-beni/blob/4545b86a131d05519050df11a424368ef9f06b4f/python/beni_rl/beni_velocity_flat_env_cfg.py)。该配置声明 actor 观测 40 维、critic 50 维、动作 7 维。并非所有未来版本或所有任务都必须使用这些维度。

| actor 索引 | 内容 | 维数 |
| --- | --- | --- |
| 0–2 | 基座角速度 | 3 |
| 3–5 | 机身坐标中的投影重力 | 3 |
| 6–8 | 速度命令 | 3 |
| 9–13 | 关节相对位置 | 5 |
| 14–20 | 关节速度 | 7 |
| 21–27 | 上一步动作 | 7 |
| 28–30 | base pose 命令 | 3 |
| 31–32 | 云台命令 | 2 |
| 33–35 | 头部角速度 | 3 |
| 36–39 | 跳跃命令槽位，平地配置中为常量 0 | 4 |

动作按 hips、knees、wheels、head_yaw 组织：L1 / R1 两个位置目标，L2 / R2 两个位置目标，LW / RW 两个速度目标，再加偏航云台位置目标。动作缩放与默认偏置由训练配置决定，不能直接把网络输出当成角度或 PWM。

critic 额外使用线速度、基座高度、轮子接触力等训练信息。训练期能访问的状态不意味着实机也能测到；部署依赖 actor 的输入契约，而不是把 critic 的特权信息照搬到硬件。

## 执行器建模的价值

[beni_robot.py](https://github.com/Mondo-Robotics/open-beni/blob/4545b86a131d05519050df11a424368ef9f06b4f/python/beni_rl/beni_robot.py) 给出了 PD 参数、力矩限制和 2–5 个 lag 的命令延迟设置。lag 是配置中的离散延迟单位，换算毫秒还要结合实际控制 / 仿真步长。

[actuator.py](https://github.com/Mondo-Robotics/open-beni/blob/4545b86a131d05519050df11a424368ef9f06b4f/python/beni_rl/actuator.py) 在电机 PD 力矩上加入被动膝弹簧项，再施加仿真力矩上限。它描述的是执行器与机构模型，不是披露量产舵机的额定参数。换成国产总线舵机时，应重新测延迟、死区、带载速度和连续输出能力。

平地环境还包含轮地摩擦、编码器偏置、重心偏移和外部扰动等随机化。对 M10 有价值的是“测量 → 建模 → 随机化 → 评估”的方法，而不是不加区分地复制参数范围。

## PPO 在系统中的位置

PPO 根据采样轨迹更新策略，通过限制新旧策略变化幅度改善训练稳定性。奖励应同时考虑完成任务与动作代价：速度跟踪、姿态和目标误差可以是正向目标，抖动、能耗、过大力矩和跌倒可作为惩罚。奖励权重不是跨机器人通用常数。

视觉层负责识别、锁定目标并给出期望线速度 / 角速度；运动策略再把期望转换为关节 / 轮子动作。运动 velocity tracking 不负责“这个人是不是主人”。通讯、急停与观测过期检查应在策略之外持续生效。

## M10 两条可选实验路线

| 路线 | 任务 | 基线 | 先决条件 |
| --- | --- | --- | --- |
| 保留差速底盘 | 速度 / 转向或视觉误差控制的研究对比 | 已标定 P / PD、可用时的轮速 PID | 测速、时延、地面摩擦和动作范围 |
| 改为轮足 / 双足 | 平衡、姿态、速度和扰动恢复 | 对应拓扑的经典控制器 | IMU、关节反馈、执行器模型和正确质量惯量 |

第一条可以先不用 RL 完成跟随。第二条改变了状态与动作空间，需要自有模型与训练。Beni 的 7 维权重不能直接控制两驱 M10，也不能因接口能加载 ONNX 就认定策略可以迁移。

## 导出和部署应固定的契约

每个模型至少配套：机器人模型版本、观测名称 / 顺序 / 单位、归一化统计、历史或循环状态、控制周期、动作缩放与限幅、关节顺序、模型哈希、训练提交、评估条件及停车回退规则。

建议分阶段比较：离线轨迹回放核对数值 → 相同种子和扰动集的仿真评估 → 架空输出检查 → 限速低风险地面 → 长时间联合运行。记录跟踪误差、跌倒 / 越界、异常停车时延和执行器温升。训练奖励提高不能替代这些验收。
