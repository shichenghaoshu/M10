# 目标跟踪与跟随控制

## 已实现的基线

1. NMS 按置信度移除同类别重复框。
2. 逐条已有轨迹，在未使用的同类检测框中选择最大 IoU。
3. IoU 严格大于默认 0.30 时沿用 Track ID，更新中心、归一化面积与相邻更新的位移。
4. 未匹配增加 `lost_frames`，超过默认 30 次更新后删除。更新次数不能直接当作秒数。

IoU 是交集面积除以并集面积。当前代码不是完整 SORT：没有 Kalman 预测，也没有匈牙利全局匹配；记录的中心差分没有用于预测。

## 需要修复的缺口

- Mac 仿真按置信度和中心偏差反复排序选择目标，尚未固定 `target_id`。
- 保留的旧轨迹仍可能进入目标选择；C++ 状态机没有直接检查传入目标的 `lost_frames`。
- Track ID 不等于真实个体身份。同类交叉、长遮挡和离开画面后的重新进入不能只靠 IoU 保证身份。

这些是静态代码发现的限制，不是已确认发生的实机事故。

## 改进方案

| 问题 | 方案 | 验证方式 |
| --- | --- | --- |
| 快速位移 | Kalman 预测和全局匹配 | 相同录像统计 ID 切换 |
| 遮挡低分框 | 借鉴 ByteTrack 两阶段关联 | 统计轨迹中断与错误恢复 |
| 目标跳换 | 固定目标 ID，重捕获加入位置门控与连续确认 | 多人 / 多宠物交叉录像 |
| 旧框驱动 | 观测时间戳与动作有效期分离 | 卡帧、掉包、旧消息注入 |
| 控制抖动 | 中心死区、P / PD、限速和加速度约束 | 中心偏差与速度变化记录 |

低分框可以帮助恢复轨迹，不应单独授权前进。框面积只作相对远近代理，不能宣称获得准确米制距离或完整避障能力。

参考：[SORT](https://arxiv.org/abs/1602.00763)、[ByteTrack](https://arxiv.org/abs/2110.06864)。改进方案尚未完成板端闭环验证。

## 源码字段与计算口径

源码：[m10_core.hpp](../m10-vision/native/common/m10_core.hpp)、[m10_core.cpp](../m10-vision/native/common/m10_core.cpp)、[sim_tracker.py](../m10-vision/sim_tracker.py)。

| 字段 / 参数 | 当前含义 | 边界 |
| --- | --- | --- |
| `track_id` | Tracker 生命周期内的编号 | 不是人脸身份或跨重启永久 ID |
| `center_x / center_y` | 框中心除以帧宽 / 高 | 归一化画面坐标 |
| `normalized_area` | 框面积 / 图像面积 | 不是米制距离 |
| `velocity_x / velocity_y` | 相邻匹配更新的中心差分 | 没除以时间，不是每秒速率 |
| `match_iou=0.30` | 关联下限 | 等于 0.30 不匹配 |
| `max_lost=30` | 未匹配更新的保留次数 | 连续第 31 次失配才删除 |
| `confidence_threshold=0.45` | C++ 决策分数下限 | 旧轨迹仍保留旧分数 |
| `target_lost_frames=15` | 无目标后进入 TARGET_LOST 的更新阈值 | 无目标时已经立即 STOP，不先等待 15 帧 |

若 T 条轨迹、D 个检测，当前关联约为 O(TD)，NMS 最坏约为 O(D²)。贪心关联可能受轨迹遍历顺序影响，没有全局最优分配。

Python `_select_target()` 筛选面积在 0.01 到 0.8、分数大于 0.2 的轨迹，按 `2 × (confidence - 0.5) - 0.5 × abs(center_x - 0.5)` 排序。它没有固定 ID，也没有排除 `lost > 0`；“保留轨迹以便重关联”和“允许它控制电机”需要分开实现。

## Android 与 C++ 不是同一个决策实验

| 判断 | C++ BehaviorMachine | Android `/api/v1/follow` |
| --- | --- | --- |
| 目标 | 调用者传入轨迹 | 单次检测列表的第一个人员框 |
| 太近 | 面积 > 0.25，后退 | 面积 > 0.30，后退 |
| 横向偏移 | 中心 < 0.38 / > 0.62 | 中心 < 0.35 / > 0.65 |
| 太远 | 先判断横向，再对面积 < 0.05 前进 | 面积 < 0.06 时先前进，再判断横向 |
| 慢行 | 分数 0.45 到 0.60 的远目标使用 SLOW_FORWARD | 检测下限固定 0.35，没有同样分支 |
| 输出 | Motion，演示程序送 Mock | JSON 动作建议，没有串口发送 |

因此“远而偏左”的目标在两个实现里可能得到不同动作。下一步应采用共享输入与决策规范。C++ 的 IDLE 等状态在健康正常、路径可行且有目标时仍可能进入几何决策，真实接入前还需增加允许运动的状态门控。

## 按什么顺序增强

1. **先做目标锁定和时效门控。** 记录 `target_id`、`frame_id`、本机单调时钟 `captured_at` 和 `matched_this_frame`。失配立即撤销前进授权，短期轨迹记忆仍可保留。
2. **增加受约束重捕获。** 用预测位置、类别、尺寸变化和连续多帧确认筛选候选；多个候选无法区分时继续停止。离开视场后重新出现不能仅凭同类框恢复身份。
3. **加入运动预测和全局关联。** Kalman 等估计需要真实 `dt`；结合类别、距离和 IoU 门控，再做匈牙利分配，并限制长时间缺测的预测有效期。
4. **再尝试低分框二次关联。** 低分框帮助保留轨迹记忆，动作权限仍使用更严格条件。
5. **必要时引入身份特征。** 轻量 ReID / 人脸辅助需要算力、阈值数据和误识率支撑。当前 `identity_match()` 仅比较传入向量，没有提取特征的模型。

以上为待实现方案，不是当前代码的功能清单。

## 平滑控制的一个可解释基线

```text
e_x = center_x - 0.5
e_a = target_area - observed_area
ω = -Kp_x × e_x - Kd_x × Δe_x / dt
v = Kp_a × e_a
v_l = v - ω × wheel_track / 2
v_r = v + ω × wheel_track / 2
```

这里约定画面向右为正、车体左转角速度为正；镜像、相机安装与电机极性需实测确认。公式产生物理速度，当前 PWM 没有轮速标定或编码器闭环，不能直接按数值写入 ±1000 目标。

实现时还需中心死区、面积滞回、速度 / 加速度限幅和非零动作期限。没有后方可行性观测时，框变大不能直接授权倒车；一个 `path_safe` 布尔量也不能表达前后方向差异。

## 延迟与验证方法

历史 Android 抓拍到决策约 600–700 ms，单次采集约 500–600 ms，推理约 75–90 ms。先改常驻采集与最新帧队列，队列满时丢旧帧，不积累迟到结果。

分别记录采集、推理、决策、发送、ACK 和物理动作时间。观测有效期与电机动作期限独立校验，持续网络心跳不能让旧视觉结果重新有效。

| 场景 | 建议指标 | 验收重点 |
| --- | --- | --- |
| 单目标横移与远近变化 | 中心误差、动作切换和速度变化 | 保持目标并减少抖动 |
| 两个同类对象交叉 | IDSW、误锁次数 | 不自动跟错对象 |
| 短 / 长遮挡、重新进入 | 重捕获时间、错误恢复 | 不确定时停止并重确认 |
| 拔相机、重复帧、推理卡顿 | 最后新鲜帧到停止的时延 | 旧框不能延长非零动作 |
| 明暗与运动模糊 | 漏检、关联中断和误动作 | 恢复轨迹与授权动作分离 |
| 同一录像对比算法 | IDSW、轨迹中断、p50 / p95 耗时 | 以相同输入比较，不用不同模型 FPS 宣称算法提升 |

这是实验计划，没有把目标值当成已经测得的结果。协议和动作期限见 [interfaces.md](interfaces.md)。
